# AGENTS.md

Android score-keeping app. Single Gradle module `:app`. UI is a single activity
(`MainActivity`) hosting navigation-graph fragments; state is held in memory and
lost on process death.

## Setup / toolchain

- Requires **JDK 21** (pinned via `jvmToolchain(21)` in `app/build.gradle.kts`).
- `local.properties` (gitignored) must point `sdk.dir` at an Android SDK with
  **API 37** (`compileSdk = 37`; `minSdk = 26`, `targetSdk = 33`).
- Bleeding-edge versions: Gradle 9.8.1, AGP 9.4.1, Kotlin 2.3.21, Hilt 2.60.1.
  Bump versions only in `gradle/libs.versions.toml`.
- Hilt annotation processing uses the **`com.android.legacy-kapt`** plugin
  (`libs.plugins.androidLegacyKapt`) plus `kapt(...)`. Do **not** add the classic
  `kotlin-kapt` plugin; use the existing alias for new kapt dependencies.

## Commands

```bash
./gradlew assembleDebug          # build the debug APK
```

There is **no `app/src/test` source set, no unit tests, no lint/ktlint/detekt
config, and no CI**. Adding a JVM test requires creating `app/src/test/...`
first; `./gradlew test` currently runs nothing meaningful. Prefer
`assembleDebug` as the quick compile check.

## Layout

Root package: `com.github.jpohlmeyer.scorekeeperkotlin`.

- `GameService.kt` — Hilt `@Singleton` holding a single mutable `var game: Game`.
  ViewModels read/mutate it directly, so game state survives navigation. Starting
  a new game replaces the `game` object (`StartViewModel.setGame`).
- `model/` — `Game` (abstract) + `Player` (open base) and one subpackage per game
  mode (`simplegame/`, `skullkinggame/`).
- `screens/<screen>/` — one package per screen, each with a `Fragment` and a
  `@HiltViewModel` `*ViewModel`. Fragments use ViewBinding (`Fragment*Binding`).
- `res/navigation/nav_graph.xml` — source of truth for navigation. Type-safe
  `*Directions` classes are generated by the safeargs plugin; navigate via
  `findNavController().navigate(SomeFragmentDirections.actionXtoY())`.
- `gameService.game` must be cast (e.g. `as SimpleGame`) in ViewModels; a
  mismatch crashes.
- `design/` is icon source artwork only (not compiled).

## Adding a game mode (multi-file wiring)

Skull King is fully implemented but **intentionally disabled** — `GameType`
only lists `SIMPLE_GAME` with a `TODO` to enable it. Adding/enabling a mode
requires touching all of:

1. `model/<mode>/` — `Game` subclass + `Player` subclass.
2. `model/GameType.kt` — add the enum entry (`SIMPLE_GAME` is the registry).
3. `res/navigation/nav_graph.xml` — fragment + actions.
4. `screens/addplayers/AddPlayersFragment.kt` `startGameOnClick` — add the
   `is <Mode>` branch that navigates to the new game fragment.
5. `screens/<mode>/` — Fragment + ViewModel.

## Conventions / gotchas

- Game/Player instances are created **reflectively**:
  `gameClass.primaryConstructor!!.call()` (StartFragment) and
  `playerType.primaryConstructor!!.call(name)` (AddPlayersFragment). Keep a
  no-arg `Game` constructor and a `(String)` `Player` constructor, or these
  `!!` calls throw. `kotlin-reflect` is a dependency for this reason.
- `Game.genericPlayerList` is the raw store. Each `Game` subclass exposes a
  typed `playerList` getter that unchecked-casts it (and returns an empty list
  if the first element is the wrong type). Keep both in sync; add new modes the
  same way.
- LiveData "refresh" pattern: after mutating a player, reassign
  `_playerLiveData[i].value = _playerLiveData[i].value` to trigger observers.
- New user-visible strings belong in `res/values/strings.xml`, dimensions in
  `dimensions.xml`, colors in `colors.xml`.
